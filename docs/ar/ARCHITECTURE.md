## مكونات المشروع

### service/ — خدمة واجهات الأعمال

يوفر جميع واجهات الأعمال لبرنامج WeChat الصغير وتطبيق Flutter. webman v2، المنفذ 8787.

**تقسيم الوحدات:**

| الوحدة | المسار | المصادقة | الوصف |
|------|------|------|------|
| الواجهة العامة | `api/` | بدون | تسجيل الدخول/التسجيل/رمز التحقق/استدعاء WeChat |
| وحدة المستخدم | `user/` | JWT | الملف/العنوان/المفضلة/الملاحظات/الترويج |
| وحدة الفني | `technician/` | JWT+فني | الملف/الجدولة/لوحة العمل/التحقق/العضويات/الأرباح/السحب |
| وحدة الخدمة | `service/` | مختلط | التصنيفات/الخدمات/البحث/المتاجر |
| وحدة الطلب | `order/` | JWT | السلة/إنشاء الطلب/الدفع/الاسترداد/التحقق/التقييم (OrderController مقسم إلى 10 trait حسب المجالات التجارية، المسارات وأسماء الدوال دون تغيير) |
| وحدة التسويق | `marketing/` | JWT | الكوبونات/بطاقات العضوية(بطاقة المرات)/النقاط/بطاقات الهدايا/مزايا الأعضاء |
| وحدة المحفظة | `wallet/` | JWT | الرصيد/الشحن/سجل المعاملات/الدفع بالرصيد |
| وحدة المحتوى | `content/` | مختلط | الشرائح الدوارة/الإعلانات/الإشعارات |
| وحدة LBS | `lbs/` | عام | المدن/المتاجر القريبة |

### admin/ — لوحة الإدارة

لوحة إدارة الكمبيوتر. webman v2 + Flutter Web، المنفذ 8787.

**الوحدات الموجودة:** المصادقة، لوحة القيادة، إدارة المستخدمين، صلاحيات الأدوار، إعدادات النظام، سجلات العمليات، رفع الملفات، الحماية الأمنية

**توزيع النماذج:** `admin/app/model/` يحتفظ بـ 6 نماذج خاصة فقط (AdminPermission/AdminRole/AdminUser/OperationLog/OperationLogDetail/SystemConfig)، وبقية النماذج تُشارك نسخة service عبر composer psr-4 (`app\model\` ← `../service/app/model/`) لتجنب ازدواج النماذج؛ الفئة الأساسية `support\Model` محاذية لـ service، وعلاقة `UserPointsExchange::user()` مدمجة في نموذج نسخة service.

**الوحدات الموسعة:** إدارة الفنيين، إدارة العضويات، إدارة المتاجر، إدارة الخدمات/المنتجات، إدارة الطلبات، الكوبونات، بطاقات العضوية، مراجعة السحب، إدارة التقييمات، إحصاءات التقارير، الإدارة المالية، إدارة المحتوى، إعدادات النظام

## المكونات الأساسية

### معرّف Snowflake

جميع المفاتيح الأساسية مولدة من `erikwang2013/snowflake-php`، BIGINT غير تلقائي، تضمن التفرد العالمي الموزع. `service/support/Model::nextId()` يعيد استخدام مثيل Snowflake واحد داخل العملية، وأُزيلت نسخ `generateId()` للـ 64 نموذجًا (توحيدًا عبر الوراثة من الفئة الأساسية).

### Hashids

معرّفات طلبات/استجابات API مشفرة عبر `erikwang2013/hashids`، تكشف سلاسل hash خارجيًا.

### مصادقة JWT

`erikwang2013/jwt-webman` Bearer Token، صالح 7 أيام، يدعم التحديث والقائمة السوداء.

### تشفير البيانات

- **طبقة API**: `erikwang2013/encryption` تشفير وفك تشفير البيانات الحساسة
- **طبقة قاعدة البيانات**: trait `erikwang2013/encryptable` تشفير وفك تلقائي للحقول

### الحماية الأمنية

- `erikwang2013/security-php`: اكتشاف 31 نوع هجوم
- `erikwang2013/poster-php`: تحقق عشوائي للعمليات الحساسة
- قفل تسجيل الدخول: 5 إخفاقات تقفل 15 دقيقة
- حد التزامن: 3 رموز صالحة كحد أقصى

### وثائق API

`hg/apidoc` يولد وثائق مواصفات OpenAPI 3.0، منفصلة للوحة الإدارة والعميل:

| الواجهة | العنوان | الوصف |
|------|------|------|
| لوحة الإدارة | `admin/ GET /api/docs` | واجهات لوحة الإدارة (JWT+RBAC) |
| العميل | `service/ GET /api/docs` | واجهات الأعمال (JWT Bearer) |

الوثائق متاحة للعامة، يمكن استيرادها إلى Swagger UI لعرض الوثائق التفاعلية.

### Elasticsearch

`erikwang2013/webman-scout` مزامنة تلقائية للنماذج مع ES، دعم البحث بالنص الكامل.

## سلسلة تنفيذ الوسائط

### وسائط service/

```
公开API:  Cors → Security(31种检测) → RateLimit → ApiVersion → Controller
用户API:  Cors → Security → RateLimit → Auth(JWT) → Controller
技师API:  Cors → Security → RateLimit → ApiVersion → Auth → TechnicianAuth → Controller
```

### وسائط admin/

```
公开API:  Cors → Security → RateLimit → Controller
管理API:  Cors → Security → RateLimit → AdminAuth(JWT) → AdminPermission(RBAC) → OperationLog → Controller
健康检查: Cors → Security → RateLimit → Controller
```

## تدفقات البيانات

### تدفق الطلب

```
客户端 → Cors → Security → RateLimit → Auth(JWT) → [TechnicianAuth] → Controller
    → Model(encryptable加解密) → BaseController(hashids编码) → JSON响应
```

### عملية الحجز

```
浏览服务 → 选门店/技师/时间 → 提交订单 → Redis锁技师3分钟
    → 微信支付 → 通知技师 → 服务开始 → 服务完成 → 评价 → 订单完成
```
