## 2. التقنية وصيغ الاختبار

- الخلفية: PHP 8.3 webman، تطبيقان (service للواجهات / admin للوحة)، يشاركان نماذج service
- إطار الاختبار: PHPUnit + Eloquent، **MySQL حقيقي + وضع التراجع عن المعاملات** (غير mock)، يُتخطى تلقائيًا عند عدم توفر DB
- تشغيل الاختبار: `cd service && php -d memory_limit=2G vendor/bin/phpunit`
- أتمتة API = اختبارات تكامل طبقة المتحكمات (إنشاء Request واستدعاء دوال المتحكم مباشرة، الكتابة في DB حقيقي، تراجع المعاملات)

## 4. استنتاج اختبارات أتمتة API

- لا توجد سكربتات اختبار مستقلة بطبقة HTTP في هذا المشروع؛ ملفات الاختبار القائمة الـ 70 كلها اختبارات تكامل لطبقة المتحكمات (DB حقيقي)،
  تغطي 35+ متحكمًا، وتعادل اختبار أتمتة الواجهات
- مصفوفة تغطية الاختبارات في §3
- **تم تنفيذ فحص دخان HTTP** (2026-08-26): المنفذ 8787 مشغول بمشروع آخر، لذا غُيّر مؤقتًا استماع `config/process.php` في service
  إلى 8791 لتشغيل الخدمة (32 worker webman + websocket + 4 مؤقتات كلها [OK])،
  وتم القياس الفعلي `GET /health` → `{"code":0,"message":"ok"}` و `GET /api/guest/services` → HTTP 200
  JSON طبيعي (معرّفات hashids مرئية)، ثم stop واسترجاع الإعدادات، صفر عمليات متبقية
- يُنصح في CI بإضافة flutter build web → E2E للمسارات الحرجة في لوحة الإدارة عبر Playwright (انظر §5)
