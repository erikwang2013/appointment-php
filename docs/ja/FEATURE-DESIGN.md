## 購入フロー

### サービス予約フロー（直接注文）

```
サービス詳細 → 注文を確認(店舗/スタッフ/時間/クーポン/備考) → サービス規約を読む
    → 注文を送信 → Redisでスタッフを3分間ロック → 微信支払い → 支払い成功
    → ユーザー+スタッフに通知 → サービス時間 → スタッフが開始を確認
    → サービス完了 → QRコード核销 → ユーザー評価 → 注文完了
```

### 商品購入フロー（カートモード）

```
商品リスト → カートに追加 → カートで確認(数量変更/削除)
    → 注文を送信 → 支払い → 発送 → 受け取り → 完了
```

## 注文ステートマシン

```
pending(待支払い) → paid(支払い済み) → confirmed(確認済み)
    → serving(サービス中) → completed(完了) → reviewed(評価済み)

pending → cancelled(キャンセル済み)
paid → cancelled
paid → refunding(返金中) → refunded(返金済み)
```

## スタッフロックメカニズム

ユーザーが注文確認ページに入ると → Redis SETNX で3分間ロック。離脱/タイムアウトで解放。

```
SETNX lock:tech:123:2026-05-26-14:00 user_456 EX 180
 → 成功: 注文を続行
 → 失敗: スタッフはすでにロック済み
```

## 返金ルール

| 条件 | 返金比率 |
|------|----------|
| 注文から15分以内 または 開始まで>6時間 | 100% |
| 開始まで≤6時間 | 90% |
| 開始済みだがサービス未確認 | 80% |
| サービス開始確認後 | 0%（返金なし）|

## 割引ルール

| タイプ | 条件 | 割引 | 併用 |
|------|------|------|------|
| オフピーク割引 | 10-12時/17-18時/21:00以降 | 9割 | クーポンと併用可 |
| 事前予約 | 30分以上前 | 95割 | クーポンと併用不可 |

## スタッフの出金

- 毎月20日に出金可能、T+1で微信零錢に到着
- 核销済み未精算：3日で自動確認
- 最低金額/保留金額/100単位制限はバックエンドで設定

### 出金フロー

```
出金申請 → poster-php検証 → バックエンド審査(承認/却下)
    → 出金完了 → 微信零錢に到着 → 財務流水を生成
```

### 収益タイプ

| タイプ | 説明 |
|------|------|
| commission | サービス歩合 |
| bonus | ボーナス(リピーター/勤怠) |
| penalty | ペナルティ(24h未記入カルテ) |
| subsidy | 補助金 |
| attendance | 皆勤ボーナス |

### リピーター報酬

同じスタッフで30日以内に2回目の消費 → ボーナスを記録

### 会員カルテ

各注文完了後24時間以内にカルテを記入必須、それ以外は歩合なし

## ポイント設計

- 消費で獲得、紹介で獲得（バックエンド設定可）
- 1:100でギフトカードと交換（バックエンド設定可）
- ポイント流水テーブルが毎回の変動+残高を記録

## 会員カード設計

| タイプ | 計費 | 説明 |
|------|------|------|
| month | 日割り | 通常月額カード |
| vip | 日割り | VIP年額カード |
| times | 回数制 | 回数券、サービス項目を自由に組み合わせ可能 |

回数券：購入時にサービス組み合わせを選択(A×3+B×5)、毎回対応する項目を1回消費。使い切ると→used_up、期限切れ→expired。

## 身分切替

```
顧客 → スタッフに切替 → スタッフカルテがapprovedか確認
    → はい: active_role=technician, ページ切替
    → いいえ: 参入申請へ誘導

スタッフ → 顧客に切替 → active_role=customer, ページ切替
```

## 新規ユーザー特典

```
登録 → 紹介コードを生成 → 紹介者がいる→紹介記録を作成
    → 新規ユーザークーポンを自動発行(Phase 5)
    → 紹介者がポイント獲得(被紹介者の初回注文後)
```

## 支払い設計（微信支払い予約）

```
POST /api/order/pay/{id}
    → 支払いレコードを作成 → 微信統一下単を呼び出し(WechatPayService予約)
    → 支払いパラメータを返す → フロントが支払いを起動
    → 微信コールバック /api/wechat/notify → 署名検証 → 状態をpaidに更新
    → ユーザー+スタッフに通知
```
