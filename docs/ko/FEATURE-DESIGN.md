## 구매 프로세스

### 서비스 예약 프로세스(직접 주문)

```
서비스 상세 → 주문 확인(매장/기술자/시간/쿠폰/메모) → 서비스 약관 열람
    → 주문 제출 → Redis 기술자 3분 잠금 → 위챗 결제 → 결제 성공
    → 사용자+기술자 알림 → 서비스 시간 도래 → 기술자 시작 확인
    → 서비스 완료 → QR 검증 → 사용자 평가 → 주문 완료
```

### 상품 구매 프로세스(장바구니 모드)

```
상품 목록 → 장바구니 담기 → 장바구니 확인(수량 변경/삭제)
    → 주문 제출 → 결제 → 발송 → 수령 → 완료
```

## 주문 상태 머신

```
pending(결제 대기) → paid(결제됨) → confirmed(확인됨)
    → serving(서비스 중) → completed(완료) → reviewed(평가됨)

pending → cancelled(취소됨)
paid → cancelled
paid → refunding(환불 중) → refunded(환불됨)
```

## 기술자 잠금 메커니즘

사용자가 주문 확인 페이지 진입 → Redis SETNX 3분 잠금. 이탈/시간 초과 시 해제.

```
SETNX lock:tech:123:2026-05-26-14:00 user_456 EX 180
 → 성공: 주문 계속
 → 실패: 기술자가 이미 잠김
```

## 환불 규칙

| 조건 | 환불 비율 |
|------|----------|
| 주문 후 15분 내 또는 시작까지 >6시간 | 100% |
| 시작까지 ≤6시간 | 90% |
| 시작했지만 서비스 미확인 | 80% |
| 서비스 시작 확인 후 | 0%(환불 불가) |

## 할인 규칙

| 유형 | 조건 | 할인 | 중첩 |
|------|------|------|------|
| 비수기 할인 | 10-12시/17-18시/21:00 이후 | 9折 | 쿠폰과 중첩 가능 |
| 사전 예약 | 30분 이상 전 | 95折 | 쿠폰과 중첩 불가 |

## 기술자 출금

- 매월 20일 출금 가능, T+1 영점 지갑 입금
- 검증 완료 미정산: 3일 자동 확정
- 최저 금액/보류 금액/100원 단위 제한은 백엔드 설정

### 출금 프로세스

```
출금 신청 → poster-php 검증 → 백엔드 심사(승인/반려)
    → 출금 완료 → 영점 지갑 입금 → 재무 거래 내역 생성
```

### 수익 유형

| 유형 | 설명 |
|------|------|
| commission | 서비스 수당 |
| bonus | 보너스(재방문 고객/근태) |
| penalty | 벌금(24h 내 프로필 미작성) |
| subsidy | 보조금 |
| attendance | 전근 보상 |

### 재방문 고객 보상

같은 기술자 30일 내 2차 소비 → 보너스 기록

### 회원 프로필

주문 완료 후 24h 내 프로필 필수 작성, 아니면 수당 없음

## 포인트 설계

- 소비 획득, 추천 획득(백엔드 설정 가능)
- 1:100 선물 카드 교환(백엔드 설정 가능)
- 포인트 거래 내역 테이블에 모든 변동+잔액 기록

## 멤버십 카드 설계

| 유형 | 과금 | 설명 |
|------|------|------|
| month | 일 기준 | 일반 월간 카드 |
| vip | 일 기준 | VIP 연간 카드 |
| times | 횟수 기준 | 횟수권, 서비스 항목 자유 조합 가능 |

횟수권: 구매 시 서비스 조합 선택(A×3+B×5), 사용할 때마다 해당 항목 1회 소모. 소진→used_up, 만료→expired.

## 신원 전환

```
고객 → 기술자 전환 → 기술자 프로필 approved 확인
    → 예: active_role=technician, 페이지 전환
    → 아니오: 입점 신청 안내

기술자 → 고객 전환 → active_role=customer, 페이지 전환
```

## 신규 사용자 보상

```
가입 → 추천 코드 생성 → 추천인 있음→홍보 기록 생성
    → 신규 사용자 쿠폰 자동 발급(Phase 5)
    → 추천인 포인트 획득(추천인의 첫 주문 후)
```

## 결제 설계(위챗페이 예약)

```
POST /api/order/pay/{id}
    → 결제 기록 생성 → 위챗 통합 주문 호출(WechatPayService 예약)
    → 결제 파라미터 반환 → 프런트엔드 결제 호출
    → 위챗 콜백 /api/wechat/notify → 서명 검증 → 상태 paid 갱신
    → 사용자+기술자 알림
```
