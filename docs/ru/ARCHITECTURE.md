## Общий обзор системы

Система сервиса предварительной записи построена по архитектуре «три платформы + два сервиса»:

```
┌─────────────────────────────────────────────────────┐
│                    Слой клиентских платформ           │
│  ┌──────────────┐  ┌──────────────┐                 │
│  │ WeChat Mini   │  │ Flutter APP   │                │
│  │ apps/wechat/  │  │ apps/flutter/ │                │
│  └──────┬───────┘  └──────┬───────┘                 │
│         │   функциональная эквивалентность           │
│         └────────┬─────────┘                         │
│                  │ смена ролей клиент/мастер          │
├──────────────────┼──────────────────────────────────┤
│                Слой бизнес-API                        │
│  ┌──────────────┐  ┌──────────────┐                 │
│  │ service/ API  │  │ admin/ API    │                │
│  │ порт 8787     │  │ порт 8787     │                │
│  └──────┬───────┘  └──────┬───────┘                 │
│         │                  │                          │
│         └────────┬─────────┘                          │
│                  │ общие MySQL/Redis/ES               │
├──────────────────┼──────────────────────────────────┤
│                  Слой данных                           │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌──────────┐     │
│  │ MySQL  │ │ Redis  │ │  ES    │ │сторонние  │     │
│  └────────┘ └────────┘ └────────┘ └──────────┘     │
└─────────────────────────────────────────────────────┘
```

## Состав проекта

### service/ — сервис бизнес-API

Предоставляет все бизнес-интерфейсы для WeChat Mini Program и Flutter APP. webman v2, порт 8787.

**Разбиение на модули:**

| Модуль | Путь | Аутентификация | Описание |
|------|------|------|------|
| Публичный API | `api/` | нет | Вход/регистрация/код подтверждения/колбэки WeChat |
| Модуль пользователя | `user/` | JWT | Профиль/адреса/избранное/обратная связь/продвижение |
| Модуль мастера | `technician/` | JWT+мастер | Анкета/расписание/рабочее место/подтверждение/участники/доход/вывод средств |
| Модуль услуг | `service/` | смешанная | Категории/позиции/поиск/филиалы |
| Модуль заказов | `order/` | JWT | Корзина/оформление/оплата/возврат/подтверждение/отзывы (OrderController разбит по бизнес-доменам на 10 трейтов, маршруты и имена методов не изменились) |
| Маркетинговый модуль | `marketing/` | JWT | Купоны/карты участника (карты посещений)/бонусы/подарочные карты/привилегии участника |
| Модуль кошелька | `wallet/` | JWT | Баланс/пополнение/история операций/оплата балансом |
| Модуль контента | `content/` | смешанная | Карусели/объявления/уведомления |
| Модуль LBS | `lbs/` | публичный | Города/ближайшие филиалы |

### admin/ — админка

PC-админка. webman v2 + Flutter Web, порт 8787.

**Имеющиеся модули:** аутентификация, дашборд, управление пользователями, роли и права, системная конфигурация, журнал операций, загрузка файлов, защита.

**Распределение моделей:** в `admin/app/model/` оставлено только 6 собственных моделей (AdminPermission/AdminRole/AdminUser/OperationLog/OperationLogDetail/SystemConfig), остальные модели через composer psr-4 (`app\model\` → `../service/app/model/`) разделяются с service-версией, что исключает расхождение двух копий моделей; базовый класс `support\Model` выровнен с service, метод отношения `UserPointsExchange::user()` перенесён в service-версию модели.

**Расширенные модули:** управление мастерами, управление участниками, управление филиалами, управление услугами/товарами, управление заказами, купоны, карты участника, проверка вывода средств, управление отзывами, статистика и отчёты, финансовое управление, управление контентом, системные настройки.

### apps/ — пользовательский фронтенд

| Каталог | Технология | Платформа |
|------|------|------|
| `apps/wechat/` | нативная WeChat Mini Program | WeChat |
| `apps/flutter/` | Flutter 3.x + GetX + Dio | iOS + Android |

## Ключевые компоненты

### Snowflake ID

Все первичные ключи генерируются `erikwang2013/snowflake-php` — BIGINT без автоинкремента, глобальная уникальность в распределённой среде. `service/support/Model::nextId()` переиспользует один экземпляр Snowflake в рамках процесса; дублированные копии `generateId()` в 64 моделях удалены (все унаследованы от базового класса).

### Hashids

ID в запросах/ответах API кодируются через `erikwang2013/hashids`, наружу отдаётся hash-строка.

### JWT-аутентификация

`erikwang2013/jwt-webman` Bearer Token, срок действия 7 дней, поддержка обновления и чёрного списка.

### Шифрование данных

- **Слой API**: `erikwang2013/encryption` шифрование/дешифрование чувствительных данных
- **Слой DB**: трейт `erikwang2013/encryptable` автоматически шифрует/дешифрует поля

### Защита

- `erikwang2013/security-php`: обнаружение 31 типа атак
- `erikwang2013/poster-php`: случайная проверка чувствительных операций
- Блокировка входа: 5 неудачных попыток — блокировка на 15 минут
- Ограничение параллелизма: не более 3 действительных токенов

### API-документация

`hg/apidoc` генерирует документацию по стандарту OpenAPI 3.0, отдельно для админки и клиента:

| Сторона | Адрес | Описание |
|------|------|------|
| Админка | `admin/ GET /api/docs` | API админки (JWT+RBAC) |
| Клиент | `service/ GET /api/docs` | Бизнес-API (JWT Bearer) |

Документация доступна публично, её можно импортировать в Swagger UI для просмотра интерактивных интерфейсов.

### Elasticsearch

`erikwang2013/webman-scout` автоматически синхронизирует модели в ES, поддержка полнотекстового поиска.

## Цепочка выполнения middleware

### Middleware в service/

```
Публичный API:  Cors → Security(31 тип проверок) → RateLimit → ApiVersion → Controller
Пользовательский API:  Cors → Security → RateLimit → Auth(JWT) → Controller
API мастера:  Cors → Security → RateLimit → ApiVersion → Auth → TechnicianAuth → Controller
```

### Middleware в admin/

```
Публичный API:  Cors → Security → RateLimit → Controller
Управленческий API:  Cors → Security → RateLimit → AdminAuth(JWT) → AdminPermission(RBAC) → OperationLog → Controller
Health check: Cors → Security → RateLimit → Controller
```

## Потоки данных

### Поток запроса

```
Клиент → Cors → Security → RateLimit → Auth(JWT) → [TechnicianAuth] → Controller
    → Model(шифрование encryptable) → BaseController(кодирование hashids) → JSON-ответ
```

### Процесс записи

```
Просмотр услуг → выбор филиала/мастера/времени → отправка заказа → Redis-блокировка мастера на 3 минуты
    → оплата WeChat → уведомление мастера → начало услуги → завершение услуги → отзыв → заказ завершён
```
