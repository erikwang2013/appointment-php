# Проектирование функций

## Процесс покупки

### Процесс записи на услугу (прямое оформление)

```
Детали услуги → подтверждение заказа (филиал/мастер/время/купон/примечание) → ознакомление с договором
    → отправка заказа → Redis-блокировка мастера на 3 минуты → оплата WeChat → оплата успешна
    → уведомление пользователя+мастера → наступило время услуги → мастер подтверждает начало
    → завершение услуги → подтверждение по QR-коду → отзыв пользователя → заказ завершён
```

### Процесс покупки товара (режим корзины)

```
Список товаров → добавить в корзину → подтверждение в корзине (изменить количество/удалить)
    → отправка заказа → оплата → отправка → получение → завершено
```

## Конечный автомат заказа

```
pending(ожидает оплаты) → paid(оплачен) → confirmed(подтверждён)
    → serving(в процессе) → completed(завершён) → reviewed(оценён)

pending → cancelled(отменён)
paid → cancelled
paid → refunding(возврат в процессе) → refunded(возвращён)
```

## Механизм блокировки мастера

Пользователь попадает на страницу подтверждения заказа → Redis SETNX блокирует на 3 минуты. При выходе/истечении времени блокировка снимается.

```
SETNX lock:tech:123:2026-05-26-14:00 user_456 EX 180
 → успех: продолжить оформление
 → неудача: мастер уже заблокирован
```

## Правила возврата

| Условие | Доля возврата |
|------|----------|
| В течение 15 минут после оформления или более чем за 6 часов до начала | 100% |
| Менее 6 часов до начала | 90% |
| Уже началось, но услуга не подтверждена | 80% |
| После подтверждения начала услуги | 0% (без возврата) |

## Правила скидок

| Тип | Условие | Скидка | Суммирование |
|------|------|------|------|
| Скидка в непиковые часы | 10-12ч/17-18ч/после 21:00 | Скидка 10% | можно суммировать с купонами |
| Ранняя запись | более чем за 30 минут | Скидка 5% | нельзя суммировать с купонами |

## Вывод средств мастера

- Вывод возможен 20-го числа каждого месяца, зачисление в кошелёк WeChat T+1
- Подтверждённые, но не оплаченные операции: автоматическое подтверждение через 3 дня
- Минимальная сумма/резервная сумма/кратность 100 настраиваются в админке

### Процесс вывода средств

```
Запрос на вывод → проверка poster-php → проверка в админке (одобрить/отклонить)
    → завершение вывода → зачисление в кошелёк WeChat → создание финансовой операции
```

### Типы дохода

| Тип | Описание |
|------|------|
| commission | Комиссия за услугу |
| bonus | Премия (постоянный клиент/посещаемость) |
| penalty | Штраф (анкета не заполнена за 24ч) |
| subsidy | Субсидия |
| attendance | Награда за полную посещаемость |

### Награда постоянному клиенту

Повторная покупка у того же мастера в течение 30 дней → записывается премия

### Анкета участника

В течение 24ч после завершения каждого заказа анкета должна быть заполнена, иначе комиссии не будет

## Проектирование бонусов

- Начисление за покупки, за приглашения (настраивается в админке)
- Обмен 1:100 на подарочные карты (настраивается в админке)
- Таблица истории бонусов фиксирует каждое изменение + остаток

## Проектирование карт участника

| Тип | Тарификация | Описание |
|------|------|------|
| month | по дням | Обычная месячная карта |
| vip | по дням | VIP годовая карта |
| times | по количеству | Карта посещений, свободный набор услуг |

Карта посещений: при покупке выбирается набор услуг (A×3+B×5), каждый раз списывается 1 посещение соответствующей позиции. Израсходована → used_up, истекла → expired.

## Смена ролей

```
Клиент → переключение на мастера → проверка, что анкета мастера approved
    → да: active_role=technician, страница переключается
    → нет: направление на подачу заявки

Мастер → переключение на клиента → active_role=customer, страница переключается
```

## Награда новому пользователю

```
Регистрация → генерация пригласительного кода → есть пригласивший → создание записи о продвижении
    → автоматическая выдача купона новому пользователю (Phase 5)
    → пригласивший получает бонусы (после первого заказа приглашённого)
```

## Проектирование оплаты (задел под WeChat Pay)

```
POST /api/order/pay/{id}
    → создание записи об оплате → вызов единого заказа WeChat (задел WechatPayService)
    → возврат платёжных параметров → фронтенд запускает оплату
    → колбэк WeChat /api/wechat/notify → проверка подписи → обновление статуса paid
    → уведомление пользователя+мастера
```
