## II. Обзор уровней защиты

```
Запрос → Nginx (безопасные заголовки + защита чувствительных файлов) → Cors (CORS + безопасные заголовки) → SecurityMiddleware (обнаружение 31 типа атак) → RateLimit (скользящее окно Redis) → Auth (JWT) → Controller
                                                                                                   ↓
                                                                                    IP-чёрный список (5 атак/60с → блокировка 15мин)
                                                                                    Блокировка учётной записи (5 сбоев/15мин → блокировка 15мин)
```

## III. Исправленные проблемы

### 3.1 У Service в CORS отсутствовали безопасные заголовки ответа → исправлено
**Файл**: `service/app/middleware/Cors.php`
- Добавлены 7 безопасных заголовков: X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy, Permissions-Policy, CSP, X-Permitted-Cross-Domain-Policies
- Теперь конфигурация заголовков совпадает с admin

### 3.2 У Service отсутствовала блокировка при неудачных входах → исправлено
**Файл**: `service/app/api/v1/controller/AuthController.php`
- В методы `login()` и `loginByCode()` добавлен счётчик неудач в Redis
- 5 сбоев/15 минут → блокировка, HTTP 429
- При сбое Redis — корректная деградация

### 3.3 Жёстко заданный CORS Origin `*` → исправлено
**Файл**: `service/app/middleware/Cors.php`, `admin/app/middleware/Cors.php`
- Теперь настраивается через переменную окружения `CORS_ALLOW_ORIGIN`
- При пустом значении по умолчанию `*` (обратная совместимость)

### 3.4 У Service отсутствовала зависимость security-php → исправлено
**Действия**:
- Добавлен `allow-plugins.erikwang2013/security-php` в composer.json
- Выполнено `composer install --no-dev` для установки зависимостей
- Файл конфигурации опубликован в `config/plugin/erikwang2013/security-php/app.php`
- Детектор CSRF Origin (`csrf_origin`) включён (режим block)

### 3.5 У Service в Nginx отсутствовал Permissions-Policy → исправлено
**Файл**: `service/docs/nginx.conf`
- Добавлено `add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;`

### 3.6 Дополнение экосистемной конфигурации → исправлено
- В `service/.env.example` и `admin/.env.example` добавлен `CORS_ALLOW_ORIGIN`
- В `service/.env.docker` и `admin/.env.docker` добавлен `CORS_ALLOW_ORIGIN`

## V. Рекомендации к исполнению

### 5.1 Рекомендация: перевести хранилище security-php на Redis (для продакшена)
**Сейчас**: оба сервиса используют хранилище типа `file` (локальные JSON-файлы)
**Риск**: при многоинстансном развёртывании IP-чёрные списки не общие, атакующий может обойти защиту, переключаясь между инстансами
**Рекомендация**: в продакшене изменить `storage.type` на `redis`

### 5.2 Рекомендация: безопасные атрибуты Session Cookie
**Сейчас**: `secure: false`, `same_site: ''`
**Риск**: Cookie может передаваться по HTTP, защита от CSRF ослаблена
**Рекомендация**: в продакшене установить `secure: true`, `same_site: 'Lax'`

### 5.3 Рекомендация: установить dev-зависимость PHPStan
**Сейчас**: `composer install --dev` не выполнен из-за сетевого таймаута
**Действия**: `composer install --dev` или `composer require --dev phpstan/phpstan`

### 5.4 Напоминание: заменить все ключи перед продакшеном
Ключи-заглушки в `.env.docker` должны быть заменены на случайно сгенерированные значения перед продакшеном:
- `JWT_SECRET_KEY`
- `HASHIDS_SALT`, `HASHIDS_ALT_SALT`
- `ENCRYPTION_KEY`, `ENCRYPTABLE_KEY`
- `DB_PASSWORD`

**Общая оценка защиты: хорошо**

- Уровни эшелонированной обороны полные (Nginx → WAF → Rate Limit → Auth → RBAC)
