### Исправления в этом раунде (обнаружено tester-php)

- 【баг】AddressController::show/update/destroy и FavoriteController::destroy не декодировали hashids — вызовы с hashid давали 404.
  Исправление на уровне корня: `BaseController::decodeId` получил совместимость с передачей чистых цифр (если hashids не декодируется и ctype_digit — вернуть как есть),
  единообразно выиграли все 89 точек вызова в репозитории; в 4 контроллера добавлен decodeId на входе. Полная регрессия пройдена.
- 【баг】при min-length hashids = 0 часть «голых» числовых ID (например, 306) случайно являлась валидной hashids-кодировкой другого ID,
  decodeId декодировал её в неверный ID (AddressControllerTest периодически давал 404, случайно воспроизводилось при многократных прогонах).
  Исправление на уровне корня: в service/admin `config/hashids.php` для подключения main `length` 0→8,
  кодировка теперь всегда ≥8 символов, что не пересекается по длине с «голыми» числовыми ID (<8 или 16 знаков), неоднозначность устранена в пространстве кодировок.
  5 последовательных прогонов AddressControllerTest подтвердили стабильность, полная регрессия пройдена.
- Жёстко заданный «день вывода 20-е» заменён на инъекцию `config('withdraw.gate_day')` (config/withdraw.php),
  исходные 4 skip-кейса «только 20-го числа» переведены на рефлексивную инъекцию дня вывода — тесты идут весь день, 0 skip.
